# Shady teapot workspace

`teapot-workspace-8x16.webp` is the previous static study. The current website
entry uses the orbiting gradient videos in `docs/media/videos/shady/`.
The matching PNG here retains the original full-resolution static study.

- Eight rows and sixteen columns: 128 distinct renders.
- First four rows: 64 simple/medium materials. Last four: 64 complex materials.
- 6144 × 1712 pixels, with no gutters, outer padding, labels, or tile frames.
- One camera, mesh, scale, background, and lighting setup throughout.

Each fragment program is compiled by Shady, assembled with `spirv-as`, validated
with `spirv-val`, and rendered by the existing Vulkan renderer. An isolated
vertex shader supplies mesh coordinates and normals through the compiler's
existing varying inputs. The procedural patterns are mapped onto the surface,
then lit in the Shady-compiled fragment shader. No compiler changes are needed.

Separate ray-marched scenes, including capability shader 093, are excluded.
The simple/medium pool also includes small materials generated by
`tools/shady_teapot_materials.py` so the final sheet does not repeat near-identical
grey examples. Selection favors visual differences; every selected source and
render has a distinct hash. The manifest records each cell's source, generated
shader hash, SPIR-V hash, complexity group, and device.

The renders are composited with the same mesh silhouette mask onto a continuous
background, with consistent soft contact shadows. There are no rectangular
background tiles. The existing Shady compiler, renderer, vertex source, and mesh
are checked for changes before and after generation.

## Rebuild

Requires a built checkout of Shady at `~/shady` (or `--shady-root`), its generated
capability/stress shader sources, Vulkan/SPIR-V tools, and Python with Pillow and
NumPy:

```sh
python tools/build-shady-teapot-workspace.py --shady-root ~/shady
node tools/build-rollout-layouts.cjs
```

Render products and per-shader caches stay under
`~/shady/build/teapot-workspace/`. Re-running reuses unchanged validated renders.
Three representative materials were independently compiled with glslang and
rendered through the same mesh pipeline; all three comparisons were exact RGB
matches. These checks are recorded under that build directory's
`reference-checks/results.json`.
